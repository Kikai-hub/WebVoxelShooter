# Voxel Tactical: браузерный шутер 5×5

Открываешь ссылку и сразу играешь: одна комната на сайте, режим «Бомба», 5 на 5, пустые места занимают боты. Тела воксельные: каждое попадание оставляет дыру, голова может разлететься на кубики, трупы лежат до конца раунда.

Это первый вертикальный срез по плану «Браузерная версия Voxel Tactical Shooter». Что уже сделано и что осталось — в конце файла.

## Быстрый старт (разработка)

Нужен Node.js 22+.

```powershell
npm install
npm run dev
```

Откройте http://localhost:5173. Сервер комнаты работает на порту 8080, Vite проксирует к нему `/api` и `/ws`.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | сервер комнаты (tsx watch) и клиент (Vite) с горячей перезагрузкой |
| `npm run build` | сборка клиента в `dist/client` и сервера в `dist/server/main.js` |
| `npm start` | запуск собранного сервера (он же раздаёт клиент из `dist/client`) |
| `npm run typecheck` | проверка типов во всём монорепо |
| `npm run test:bots -- 100 quarter` | автотест «5 ботов против 5 ботов» на N матчей без сети (карта: `market`, `wasteland`, `quarter` или `all` — с голосованием) |
| `npm run test:zones -- caravan` | где гибнут стороны и где застревают боты (для правки карт) |
| `npm run test:net -- 60 100 50 medina` | сеть: настоящий сервер и 3 клиента по WebSocket с задержкой 100±50 мс; расхождение предсказания, видимость союзников и врагов, частота снапшотов |
| `npm run test:duel -- medium 16 vikhr` | дуэль: за сколько секунд бот убивает неподвижного игрока в броне |

## Управление

WASD — ход, Пробел — прыжок, C или Ctrl — присесть, E — заложить или обезвредить бомбу, а рядом с оружием на земле — подобрать его, R — перезарядка, 1/2/3 и Q — оружие, 4 — гранаты (повторное нажатие переключает тип), G — выбросить оружие, B — покупка (в заморозке и первые 20 с раунда на своей базе), Tab — таблица, Enter — чат, ПКМ — прицел снайперской винтовки, ЛКМ мёртвым — переключить наблюдение.

## Устройство

```
shared/   общая симуляция: карта, движение, лучи, тело и хитбоксы, оружие, протокол, навсетка
server/   сервер комнаты: раунды и экономика, боты, аккаунты, HTTP API и WebSocket
client/   клиент на Three.js: меню, карта, воксельные тела, раны, рэгдолл, HUD
tools/    тест ботов, скрипт обновления, тестовые аккаунты для локальной разработки
deploy/   Caddyfile
```

- **Сервер авторитарный.** Клиент шлёт только кнопки и углы камеры (`UserCmd`, 64 Гц, по 3 последние команды в пакете). Сервер считает движение, попадания, урон и раны. Снапшоты 30 Гц, бинарные, позиции квантованы до 16 бит.
- **Предсказание и интерполяция.** Клиент запускает тот же `shared/physics.ts`, что и сервер, и переигрывает неподтверждённые команды. Ошибку до 1 м сглаживает, больше 1 м — исправляет резко. Чужие игроки интерполируются с задержкой 100 мс.
- **Компенсация задержки.** История позиций на 32 тика, откат до 200 мс при проверке попадания.
- **Отсечение невидимых.** Сервер не присылает позицию врага, если между игроками нет прямой видимости (с упреждением по скорости).
- **Раны.** Сервер определяет часть тела и воксель входа и выхода и рассылает операции раны; клиенты применяют их одинаково. Разлёт головы — 40% хедшотов, решает сервер. Поздно вошедший получает полный список ран и трупов.
- **Боты.** Работают на сервере, шлют те же `UserCmd`. Видят только по линии обзора, слышат выстрелы, реагируют за 0,5–0,8 с (средний уровень), наводятся с ошибкой и дрожанием прицела, стреляют короткими очередями и обычно останавливаются перед стрельбой. Защитники держат позиции у укрытий и подтягиваются на сообщения союзников; боты ставят и обезвреживают бомбу. Уровень задаётся `BOT_LEVEL` (easy, medium, hard). Боты покупают и бросают гранаты: траекторию считают той же физикой полёта (медианный промах около 1 м). Нападение перед входом на точку закрывает дымом подход защиты и бросает светошумовую навесом так, чтобы она взорвалась в воздухе перед защитниками; бросивший отворачивается и предупреждает союзников рядом. Осколочную кидают туда, где только что скрылся противник. Защита отвечает дымом на место прорыва и осколочными или вспышками по услышанному, но невидимому врагу. Время убийства неподвижного игрока в броне с винтовки на 16 м: лёгкий ~3,9 с, средний ~2,1 с, сложный ~1,1 с.
- **Навигация ботов в несколько уровней.** Сетка 0,5 м, до 4 поверхностей в столбце (земля, ступени, крыши); переход — при перепаде не больше ступени, как в физике. Недостижимые поверхности отсекаются обходом от точек появления. Часть защитников (30%) держит точку с крыши или площадки рядом, часть нападающих (15%) прикрывает сверху. Карты и навсетки собираются один раз при старте сервера, смена карты не тормозит тик.
- **Анимации агентов** — только картинка в клиенте (хитбоксы на сервере по позе без анимации): шаг и бег, присед с согнутыми коленями, прыжок и приземление, отдача, перезарядка, поворот на месте; хват оружия двумя руками (руки сгибаются в локтях к точкам хвата). Стенд для настройки: `/anim.html` при `npm run dev`.
- **Модели и звуки оружия.** Шесть стволов — модели из Low Poly Weapons Pack (OBJ + MTL в `client/public/models/weapons`), приведены к виду «дуло вдоль −Z, начало в рукояти» в `client/src/game/weaponModels.ts`; от первого лица, в руках агентов и на земле. Нож и гранаты — блочные. Выстрелы — студийные записи (по 3 варианта на ствол, `client/public/sounds`), нарезаны скриптом `npx tsx tools/importWeaponSounds.ts "<папка Master Tracks>"`: моно 48 кГц, начало точно по выстрелу, затухание; вдали тише, глуше и с задержкой звука. Стенд моделей: `/weapons.html`.
- **Аккаунты.** Логин и пароль без почты. Пароли и коды восстановления хранятся только как хэши scrypt (встроенный `node:crypto`, без нативных модулей), токены сессий — как SHA-256. Есть лимит попыток, блокировка после 5 ошибок, смена пароля, восстановление по коду, «выйти со всех устройств» и удаление аккаунта. Хранилище — `data/accounts.json`.

## Установка на сервер одной командой

Нужен сервер с Ubuntu или Debian и доступ root. Домен должен указывать на IP сервера (запись A).

```sh
curl -fsSL https://raw.githubusercontent.com/Kikai-hub/WebVoxelShooter/main/deploy/install.sh | sudo bash -s -- --domain webgame.kikaidevtest.site
```

Скрипт `deploy/install.sh` ставит git и Docker, скачивает проект в `/opt/voxel-tactical`, создаёт `.env` со случайным `ADMIN_SECRET`, собирает образы, запускает сайт и включает автообновление. Без `--domain` сайт поднимется по IP на обычном HTTP (только для тестов). Повторный запуск безопасен: код обновится, `.env` и аккаунты сохранятся. Параметры: `--dir`, `--branch`, `--repo`, `--no-autoupdate`.

Поднимаются два контейнера: `game` (сервер комнаты, Node.js 22, без root, с проверкой здоровья) и `proxy` (Caddy: сертификат, раздача клиента, проксирование `/api` и `/ws`). Данные аккаунтов лежат в томе `game_data` и переживают обновления.

**Автообновление с GitHub.** Таймер systemd `vts-update.timer` раз в час запускает `deploy/update.sh`: если в ветке появились новые коммиты, скрипт скачивает их, собирает новые образы (игра в это время идёт), отправляет `drain` — комната доигрывает текущий матч (или закрывается сразу, если людей нет) — и запускает новую версию. Вручную: `bash /opt/voxel-tactical/deploy/update.sh` (`--force` — пересобрать без новых коммитов). Журнал: `journalctl -u vts-update`.

**Новости в меню.** Файл `news.json` в корне: короткие записи об обновлениях (дата, заголовок, пункты). Первая показывается в меню как «Последнее обновление», под ней номер версии (коммит). При каждом обновлении добавляйте запись в начало файла.

**Резервная копия данных:**

```sh
docker run --rm -v voxel-tactical_game_data:/data -v "$PWD":/backup alpine tar czf /backup/data-backup.tgz -C /data .
```

**Бан игрока:**

```sh
curl -X POST https://<домен>/api/admin -H 'content-type: application/json' -d '{"secret":"<ADMIN_SECRET>","cmd":"ban","login":"<ник>","reason":"читы"}'
```

GitHub Actions (`.github/workflows/docker.yml`) на каждый пуш в `main` проверяет типы, гоняет тест ботов на 30 матчей, собирает и кладёт образы в `ghcr.io`.

Для разработки в контейнере: `docker compose -f docker-compose.dev.yml up`.

## Что сделано в этом срезе

- Монорепо на TypeScript: общая симуляция для клиента и сервера.
- Три карты (воксели 0,5 м), у каждой две точки бомбы, три маршрута и нет прострела от базы до базы:
  - «Рыночная площадь», 48×48 м — средняя дистанция, сильный центр, арки;
  - «Пустошь», 60×60 м — открытая, длинные тропы, скалы и развалины;
  - «Старый квартал», 44×44 м — тесные переулки, проходные дома, крыша над двором (лестница, подъём на ступеньки в общей физике).
  - «Караван-сарай», 62×62 м — длинная крытая галерея к A, извилистый туннель через кирпичный квартал к B, двор с колодцем под навесом;
  - «Медина», 60×60 м — петляющий переулок к «Красильням» (A), крытый базар с прилавками, длинная улица к «Складам» (B), дом с лестницей на крышу.
- Голосование за карту: после таблицы матча 20 с, большинство голосов, при ничьей — случайная из лидеров; если все проголосовали — через 3 с.
- Полный раунд «Бомба»: заморозка 10 с с покупкой, 1:55 на раунд, закладка 3 с, таймер 40 с, обезвреживание 10 с, экономика (800 / 3250 / 1900 + бонус за серию), матч до 13 побед (максимум 24 раунда, смена сторон после 12-го), при 12:12 — овертайм по 4 раунда до 3 побед с $10 000 в начале каждой половины (при 2:2 — следующий овертайм), таблица результатов 20 с.
- Одна комната: боты на пустых местах, вход живого игрока вместо бота (сразу, если бот мёртв или идёт заморозка), удержание места 60 с при обрыве, очередь наблюдателей (до 20).
- Оружие (реальные названия): нож; пистолеты Glock-17, Beretta 92, Colt Python, Desert Eagle, S&W Model 29; ПП MAC-10, Скорпион vz. 61, UMP-45, MP5; дробовики Remington 870 и обрез; винтовки АК-47, M4A1, Steyr AUG; снайперские Мосин-Наган и AWM; броня и шлем. Внутренние ключи (`osa`, `vikhr`…) не меняются — на них завязано сохранённое снаряжение.
- Гранаты (до 1 осколочной, 2 светошумовых, 1 дымовой, 1 зажигательной): полёт с отскоками считается одним кодом на сервере и в клиенте. Осколочная — до 98 урона в радиусе 6 м с проверкой укрытия и ранами на теле; светошумовая ослепляет в зависимости от того, смотрел ли игрок на вспышку (у ботов — тоже); дымовая — облако из вокселей на 15 с, сквозь него не видят ни игроки (сервер не присылает позиции), ни боты.
- Сколы стен (только картинка): пуля выбивает под-воксели 12,5 см на глубину до 2 слоёв у краёв и на поверхности стен, арок, ступеней и ящиков; вскрытые грани темнее, на дереве — тёмные пробоины, осколки цвета материала разлетаются. Осколочная граната выбивает выбоины в стенах и ящиках вокруг и воронку в полу (лучи во все стороны: рядом крупнее, дальше мельче) и оставляет кольцо копоти. Коллизия, прострел и видимость не меняются. Лимит — 2000 сколов за раунд и 30 на блок; сервер рассылает операции, поздно вошедший получает список, в начале раунда стены восстанавливаются. Перестройка чанка со сколами — 0,25–0,4 мс.
- Набор сапёра ($400, только защита): обезвреживание за 5 с вместо 10; сгорает при смерти, переживший раунд оставляет его, при смене сторон сбрасывается. Боты защиты обычно его покупают.
- Оружие на земле: при смерти выпадает основное (или купленный пистолет), G — выбросить, E — поднять с обменом, основное поднимается на ходу, если слот пуст.
- Клиент: меню с агентом по центру и размытым кадром карты на фоне, вход и регистрация, инвентарь, снаряжение по сторонам с раскрасками (хранится на сервере, выбранное оружие первым в меню покупки), настройки (чувствительность, поле зрения, трассеры и их яркость, режим «конфетти», громкость).
- 3D: пиксельные текстуры с фильтром «ближайший пиксель», меш карты по чанкам 16³ с запечённым затенением в углах, воксельные тела из 6 частей (~1300 вокселей по 6 см), раны с тёмным мясом под кожей, разлёт головы, рэгдолл с коленями и локтями (колено гнётся только вперёд, локоть — назад), толчком сильнее у задетой части, инерцией бега и подламыванием ног при хедшоте; «удержание мышц» 0,1–0,5 с, кубики крови и осколки (до 2000), следы пуль и пыль, трассеры (светло-жёлтые у игроков, оранжевые у ботов), автоматическое снижение разрешения при просадке FPS.
- HUD: таймер, счёт, портреты, круглая миникарта с названием зоны, здоровье, броня, деньги, патроны, слоты, лента убийств, чат, индикатор урона, прогресс закладки и обезвреживания, таблица по Tab.
- Docker: многоступенчатый образ, compose с Caddy, dev-compose, CI.

Результаты `npm run test:bots -- 30 <карта>` (около 300 раундов на карту): нападение выигрывает 55% на «Рыночной площади», 57% на «Пустоши», 56% на «Старом квартале» (критерий — не больше 60/40), 99-й процентиль тика около 0,2 мс (критерий — не больше 4 мс). Между прогонами доля плавает на несколько процентов, поэтому после правок ботов или карт прогоняйте тест не один раз. Docker-стек проверен локально: `game` healthy, клиент и WSS идут через Caddy, 30 снапшотов в секунду.

## Обновление: команды, статистика, управление, зажигательные

- **Смена команды — M.** Место берётся у бота другой стороны, старое место отдаётся боту. Мёртвым, в заморозке и между раундами — сразу, иначе — в начале следующего раунда. Убийства, смерти и деньги сохраняются.
- **Ники над головами союзников** (у наблюдателя — у всех), с здоровьем, если оно не полное.
- **Зажигательные.** «Коктейль Молотова» ($400, только атака) и «Зажигательная граната» ($600, только защита): разбиваются о пол (или через 2 с в воздухе), огонь радиусом 3 м горит 7 с, 40 урона в секунду врагам, броня не спасает. Дымовая тушит огонь, в дыму зажигательная не загорается. Боты покупают, бросают и выходят из огня.
- **Статистика** (вкладка в меню): убийства, смерти, K/D, MVP, доля в голову, точность, урон за раунд, убийств в минуту и в секунду, раунды и матчи с процентом побед, время в игре, любимое оружие и топ-5 стволов. Хранится в аккаунте (`/api/stats`). MVP раунда — из победившей команды по убийствам, урону и бомбе.
- **Управление** (Настройки → Управление): до двух клавиш на действие, захват клавиши по клику, «Сбросить по умолчанию». Хранится в настройках аккаунта, сервер проверяет коды. Подсказка в паузе строится по текущим клавишам.

## Обновление: комментатор, продажа, вид зрителя
